# Email Server Setup Guide (Stalwart)

This guide outlines the architecture, network requirements, DNS configuration, and Docker setup required to host your own email server using **Stalwart Mail Server**.

## 1. Firewall & Cloudflare Tunnel Architecture

**Can it run via Cloudflare Tunnel Zero Trust?**
**No**, not entirely. Cloudflare's standard (free) Zero Trust Tunnels only proxy HTTP/HTTPS traffic. Email relies on TCP protocols (SMTP, IMAP) that Cloudflare Tunnels cannot route publicly without Enterprise features (Cloudflare Spectrum).

**The Hybrid Approach:**
*   **Must be Public (Exposed via VPS Firewall):** The actual mail protocols must be routed directly to your VPS's public IP address.
*   **Can use Cloudflare Tunnel:** The Web Administration Panel and Webmail interface can be securely routed through your existing Cloudflare Tunnel.

**Firewall Ports to Open on your VPS (UFW / Host Firewall):**
You must open the following ports to the public internet:
*   `25` (SMTP) - Crucial for server-to-server email delivery.
*   `587` (SMTP Submission) - For your email clients to send mail securely.
*   `465` (SMTPS) - Legacy secure submission.
*   `143` (IMAP) - For clients to read mail.
*   `993` (IMAPS) - Secure IMAP.
*   `4190` (ManageSieve) - Optional, for email filtering rules.

*Command to open on Ubuntu with UFW:*
```bash
sudo ufw allow 25,587,465,143,993,4190/tcp
```

> **Warning:** Many VPS providers (like DigitalOcean, Vultr, AWS, Google Cloud) block Port 25 by default to prevent spam. You will likely need to open a support ticket with your hosting provider and ask them to "Unblock Port 25 for legitimate email server usage".

## 2. DNS Configuration (In Cloudflare)

Since email cannot use the Cloudflare Proxy (Orange Cloud) for its primary traffic, you must configure your DNS records carefully.

Go to your Cloudflare Dashboard -> DNS -> Records and add the following:

### A Record (The Mail Server IP)
*   **Type:** `A`
*   **Name:** `mail`
*   **IPv4 address:** `YOUR_VPS_PUBLIC_IP`
*   **Proxy status:** ⚠️ **DNS only (Gray Cloud)** - *CRITICAL! If this is proxied, email will fail.*

### MX Record (Mail Exchange)
Tells the internet where to deliver emails for your domain.
*   **Type:** `MX`
*   **Name:** `@` (Root domain)
*   **Mail server:** `mail.yourdomain.com`
*   **Priority:** `10`

### TXT Record (SPF - Sender Policy Framework)
Authorizes your server to send emails on behalf of your domain.
*   **Type:** `TXT`
*   **Name:** `@`
*   **Content:** `v=spf1 mx a:mail.yourdomain.com -all`

### TXT Record (DMARC)
Tells receiving servers what to do if an email fails SPF/DKIM checks.
*   **Type:** `TXT`
*   **Name:** `_dmarc`
*   **Content:** `v=DMARC1; p=quarantine; rua=mailto:admin@yourdomain.com;` (Replace with your email)

### TXT Record (DKIM - DomainKeys Identified Mail)
*You will generate this inside the Stalwart Admin interface later, but the structure looks like this:*
*   **Type:** `TXT`
*   **Name:** `selector._domainkey` (Stalwart will provide the exact selector name)
*   **Content:** `v=DKIM1; k=rsa; p=...[long public key]...`

### Reverse DNS (PTR Record)
*Note: This is NOT done in Cloudflare.* You must configure this in your **VPS Provider's Control Panel** (e.g., Hetzner, DigitalOcean dashboard). You must set the Reverse DNS of your VPS IP address to `mail.yourdomain.com`. Without this, your emails will go directly to spam.

## 3. Docker Setup (Stalwart Mail Server)

We will create a dedicated folder for the mail server to keep it isolated but easily managed alongside your other apps.

### Directory Structure
```text
/apps/mail-server/
├── docker-compose.yml
└── data/ (Auto-generated by Docker to store emails/config)
```

### `docker-compose.yml`

Create this file in your `apps/mail-server/` directory:

```yaml
version: '3.8'

services:
  stalwart-mail:
    image: stalwartlabs/stalwart:latest
    container_name: stalwart-mail
    restart: unless-stopped
    ports:
      # SMTP
      - "25:25"
      - "587:587"
      - "465:465"
      # IMAP
      - "143:143"
      - "993:993"
      # Sieve (Filters)
      - "4190:4190"
      # Admin UI (Exposed locally, but Cloudflare can access directly via container name)
      - "127.0.0.1:8080:8080"
    volumes:
      - ./etc:/etc/stalwart
      - ./data:/var/lib/stalwart
    environment:
      - TZ=UTC # Adjust to your timezone if needed
    networks:
      - mail-net

  snappymail:
    image: djmaze/snappymail:latest
    container_name: snappymail
    restart: unless-stopped
    # Cloudflare Tunnel will access this internally via http://snappymail:8888
    volumes:
      - ./snappymail-data:/var/lib/snappymail
    environment:
      - TZ=UTC
    networks:
      - mail-net

networks:
  mail-net:
    external: true
```

### Next Steps to Proceed

1.  **Create Docker Network:** Run `docker network create mail-net` on your VPS. This allows Cloudflare to talk to your containers directly by name.
2.  **Verify Port 25:** Ensure your VPS provider has unblocked port 25.
3.  **Create Folders & Set Permissions:** Stalwart runs as a secure, non-root user (UID 2000). You must create the folders and give it ownership so it can save your configuration:
    ```bash
    mkdir -p data etc
    sudo chown -R 2000:2000 data etc
    ```
4.  **Run the Container:** Run `docker compose up -d` in the folder.
5.  **Get Temporary Password:** Run `docker logs stalwart-mail | grep password` to get your temporary setup password.
6.  **Setup Cloudflare Tunnels (Zero Trust):**
    *   **Admin Panel:** Route `mailadmin.yourdomain.com` to `http://stalwart-mail:8080`
    *   **Webmail:** Route `webmail.yourdomain.com` to `http://snappymail:8888`
7.  **Run Setup Wizard:** 
    *   Go to `https://mailadmin.yourdomain.com/admin` (You must append `/admin` to see the UI).
    *   Log in with username `admin` and the temporary password from the logs.
    *   Complete the 5-step setup wizard. It will generate your **real** admin email and permanent password at the end.
8.  **Configure Webmail (SnappyMail):**
    *   To log into the SnappyMail Admin panel, you need the auto-generated password. Run this command on your VPS to get it:
        ```bash
        cat ~/orchestrator/apps/mail-server/snappymail-data/_data_/_default_/admin_password.txt
        ```
    *   Go to: `https://webmail.yourdomain.com/?admin`
    *   **Username:** `admin`
    *   **Password:** *(Paste the password from the command above)*
    *   **TOTP Code:** *(Leave this completely blank!)*
    *   Once inside, immediately go to **Security** to change the admin password, then link SnappyMail to your IMAP/SMTP server (`stalwart-mail`).

## 4. How to Manage and Use Your Email

Because we split the backend (server) from the frontend (webmail), here is how your daily workflow will look:

### 1. Creating Email Accounts (Stalwart Admin)
You will create all of your email addresses (e.g., `admin@yourdomain.com`, `contactus@...`) inside the **Stalwart Admin Panel** (`mailadmin.yourdomain.com`). 
*   Navigate to **Directory > Accounts** to create users and assign their passwords. 
*   Stalwart is your central "control room" for domains, user accounts, routing, and security.

### 2. Reading and Sending Emails (SnappyMail Webmail)
Once the account is created in Stalwart, you will go to **SnappyMail** (`webmail.yourdomain.com`).
*   SnappyMail is purely your "viewer" (exactly like the Gmail app or Microsoft Outlook, but in your browser). 
*   You simply type in the email address and the password you just created in Stalwart to log in. From there, you can read your inbox, compose messages, and manage contacts.
